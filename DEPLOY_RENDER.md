# Deploy to Render + Neon (free tiers)

This project needs a persistent PostgreSQL database for account sessions and game data. The Render service is configured for the free web-service tier; Neon provides the PostgreSQL database.

## Steps

1. Create a free PostgreSQL project at https://neon.tech/ and copy its pooled connection string. Keep it private.
2. In Render, choose **New → Blueprint**, connect this GitHub repository, and select the `deploy/render-neon` branch (or merge this change into `main` first).
3. During Blueprint setup, provide the Neon connection string as `DATABASE_URL`. Render generates `BETTER_AUTH_SECRET` automatically.
4. Deploy. Render provides the public `onrender.com` URL, which the app detects using `RENDER_EXTERNAL_URL`.
5. Open the deployed site and test account creation, sign-in, sign-out, and a saved game action.

## Authentication notes

- Email/password registration is enabled in this repository.
- Google/X sign-in buttons are hidden on this deployment unless you configure this app's own `GROK_AUTH_CLIENT_ID` and `GROK_AUTH_CLIENT_SECRET` (and set `VITE_GROK_OAUTH_ENABLED=true`). Do not reuse the preview-only OAuth client for a public domain.
- The build runs `npm run db:migrate` and applies the project's SQL migrations to `DATABASE_URL`.
- Free web services may sleep when idle and wake on the next visit. Free database limits and policies can change; check the provider dashboard before relying on it for production data.

## Required environment variables

- `DATABASE_URL`: Neon PostgreSQL connection string.
- `BETTER_AUTH_SECRET`: generated by Render.
- `VITE_AUTH_ENABLED=true`
- `VITE_GROK_OAUTH_ENABLED=false` unless valid OAuth broker credentials are configured.

Do not commit secrets to GitHub or paste them into chat.
